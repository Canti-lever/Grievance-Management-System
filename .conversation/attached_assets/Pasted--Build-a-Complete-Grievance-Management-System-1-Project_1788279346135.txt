# Build a Complete Grievance Management System

## 1. Project Objective

Build a **production-quality, fully functional Grievance Management System** as a full-stack web application.

The application must have:

* **Frontend:** React.js
* **Backend:** Node.js + Express.js
* **Database:** SQLite initially
* **ORM:** Prisma ORM preferred
* **Authentication:** Secure session/JWT-based authentication
* **File Uploads:** Local filesystem initially, with clean architecture so storage can later be changed to S3/cloud storage
* **API:** REST API
* **Responsive Design:** Desktop, tablet and mobile
* **UI:** Modern, clean, accessible and extremely user-friendly

The application should be designed for users from **any technical or non-technical background**. Avoid unnecessary technical terminology, complicated navigation, or confusing workflows.

The application should feel like a modern government/public-service grievance platform: trustworthy, simple, professional, accessible and transparent.

Do NOT build only a frontend prototype. Implement the complete frontend + backend + database + authentication + CRUD operations + workflow + file upload + validation + audit logging.

---

# 2. Core Workflow

Implement this complete grievance lifecycle:

```text
USER SUBMITS GRIEVANCE
        ↓
GRIEVANCE ID GENERATED
        ↓
SUBMITTED
        ↓
ADMIN REVIEWS
        ↓
ACKNOWLEDGED
        ↓
ADMIN ASSIGNS OFFICER
        ↓
ASSIGNED
        ↓
OFFICER INVESTIGATES
        ↓
IN PROGRESS
        ↓
OFFICER/ADMIN ADDS RESOLUTION
        ↓
RESOLVED
        ↓
USER VIEWS RESOLUTION
        ↓
USER ACCEPTS RESOLUTION
        ↓
CLOSED
```

The allowed statuses are:

```text
SUBMITTED
ACKNOWLEDGED
ASSIGNED
IN_PROGRESS
RESOLVED
CLOSED
```

Enforce valid status transitions in the backend.

# 3. Design Philosophy

The most important requirement is **user friendliness**.

The application should be understandable by someone who is not familiar with computers.

Follow these UX principles:

* Use simple language.
* Use clear labels.
* Use large clickable buttons.
* Avoid unnecessary fields.
* Show helpful hints below complex fields.
* Clearly indicate required fields with `*`.
* Display meaningful validation messages.
* Never expose raw technical errors to users.
* Use confirmation dialogs for destructive actions.
* Show loading states.
* Show success/error notifications.
* Keep navigation consistent.
* Make the current page obvious.
* Make status visually understandable.
* Use icons together with text, not icons alone.
* Provide empty states instead of blank screens.
* Make tables responsive.
* Use mobile-friendly cards when tables become difficult to read.
* Maintain good color contrast.
* Make forms keyboard accessible.
* Make focus states visible.
* Use semantic HTML and accessible components.

# 50. Important Data Ownership Rules

Implement strict authorization.

### USER

Can:

```text
Create own grievance
View own grievances
View own grievance details
View own status history
View own resolution
Accept own resolution
Update own profile
View own notifications
```

Cannot:

```text
View another user's grievance
Assign officers
Change arbitrary status
Modify resolution
View audit logs
Manage users
```

### OFFICER

Can:

```text
View assigned grievances
Update assigned grievance status
Add resolution
View relevant attachments
View relevant history
```

Cannot:

```text
Manage administrators
Manage categories
Manage system settings
View unrelated grievances
```

### ADMIN

Can manage the entire system according to permissions.
